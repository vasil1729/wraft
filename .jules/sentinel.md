## 2024-07-09 - Authentication Timing Attack and Account Enumeration Vulnerabilities
**Vulnerability:** Timing attacks and account status enumeration in authentication flows (`session_controller.ex` and `user_controller.ex`). In `session_controller.ex`, checking `is_deactivated` before `Bcrypt.verify_pass` allowed enumerating deactivated accounts via early exit. In both controllers, short-circuiting `with` statements without calling `Bcrypt.no_user_verify()` allowed enumerating non-existent email addresses due to differing execution times.
**Learning:** In Elixir, early exits in `with` statements can skip computationally expensive operations like `Bcrypt.verify_pass/2`. To prevent timing attacks, always map the failure path of user lookups to `Bcrypt.no_user_verify()`. To prevent account enumeration, never check business logic flags (like `is_deactivated`) before password verification, and always return generic error messages (e.g., mapping `{:error, :invalid_email}` to `{:error, :invalid}`).
**Prevention:** Always extract user lookup into a `case` statement that handles the error path by calling `Bcrypt.no_user_verify()`. Perform password verification *before* any account status checks. Map specific lookup errors to generic errors to prevent information leakage.
