## 2024-03-24 - [Fix Authentication Timing and Enumeration Vulnerability in UserController]
**Vulnerability:** The application was susceptible to timing and user enumeration attacks during the login process (`signin/2`). When a non-existent email was provided, the system returned an `{:error, :invalid_email}` error very quickly because `Bcrypt.verify_pass/2` wasn't executed, and `FallbackController` rendered "No user with this email.!". For valid emails with incorrect passwords, it took longer due to hashing, and returned a different generic error.
**Learning:** `with` blocks inherently leak error tuples when conditions fail. Short-circuiting user lookups without hashing delays creates a timing side-channel, and exposing specific errors (e.g., `:invalid_email`) through a `FallbackController` allows user enumeration.
**Prevention:** Always extract user lookups into a defensive `case` block in authentication flows. For any lookup failure (`_ ->`), explicitly call `Bcrypt.no_user_verify()` to simulate hashing time, and map all auth failures to a generic error like `{:error, :invalid}`.
