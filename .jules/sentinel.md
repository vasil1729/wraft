## 2024-05-24 - [Fix timing attack in Elixir `with` statements]
**Vulnerability:** Timing attack and user enumeration on the login endpoint due to short-circuiting `with` statements upon failed user lookups (`Account.find`). This bypassed `Bcrypt.no_user_verify()`, allowing attackers to measure response times to verify valid emails. Furthermore, the `{:error, :invalid_email}` response leaked email non-existence.
**Learning:** In Elixir authentication flows, short-circuiting `with` statements can cause severe timing leaks if the password verification process is skipped. To prevent double-hash timing attacks, you must completely separate the execution paths of `Bcrypt.verify_pass/2` and `Bcrypt.no_user_verify/0`. Blindly nesting `if`s breaks implicit error fallthrough to the FallbackController.
**Prevention:** Extract user lookups into a separate `case` block before the `with` statement. Conditionally inject `Bcrypt.no_user_verify()` on failure with a wildcard catch-all (`_ ->`), and map the result to a generic error (`{:error, :invalid}`) to pass into the original `with` statement.
