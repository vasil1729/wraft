## 2024-05-15 - User Enumeration via Implicit `with` Statement Fallthroughs and Timing Attacks
**Vulnerability:** User enumeration vulnerability through implicit `with` statement fallthroughs and timing side-channels in the `UserController.signin` flow. The original implementation allowed early failure if `Account.find` failed (returning `{:error, :invalid_email}` implicitly passed to `FallbackController` which leaked the existence). Even worse, an attacker could observe the time differential because `Bcrypt.verify_pass` was skipped.
**Learning:** Using `with` statements without a defensive `case` block around user lookup exposes two attack vectors: it implicitly returns specific lookup errors (like `invalid_email` instead of a generic `invalid` or `not_found`), and it fails to run a dummy hashing operation (like `Bcrypt.no_user_verify()`), creating a timing side-channel.
**Prevention:** Extract user lookups in authentication flows into a dedicated `case` statement. In the catch-all (`_ ->`) clause, explicitly trigger `Bcrypt.no_user_verify()` to standardize response time, and map any lookup errors to a generic `{:error, :invalid}` before continuing or returning. Ensure edge cases like missing passwords map to a generic `{:error, :no_data}` before the lookup to prevent enumeration there as well.
