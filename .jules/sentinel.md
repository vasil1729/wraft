## 2024-05-19 - Timing Attack in Authentication Elixir with Statements
**Vulnerability:** The application had a timing attack vulnerability in `WraftDocWeb.SessionController` and `WraftDocWeb.Api.V1.UserController`. Using `with` statements, the authentication flow early-exited when an invalid email was provided. Because the bcrypt hashing wasn't executed for invalid emails, attackers could enumerate valid email addresses based on response times. Furthermore, `is_deactivated` status was checked before checking `Bcrypt.verify_pass`.
**Learning:** In Elixir authentication flows, short-circuiting `with` statements or checking account status before running `Bcrypt.verify_pass` causes timing leaks that allow enumeration of users and their status.
**Prevention:** Explicitly use `Bcrypt.no_user_verify()` on failure paths (such as when `nil` or `{:error, :invalid_email}` is returned by user lookup) to simulate password hashing delays. Additionally, verify passwords before checking business logic status flags like `is_deactivated`.
