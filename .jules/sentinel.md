## 2024-05-16 - Timing Attack Mitigation in Authentication Flows
**Vulnerability:** Elixir authentication flows (like `signin` in `WraftDocWeb.Api.V1.UserController` and `create` in `WraftDocWeb.SessionController`) were vulnerable to user enumeration timing attacks. When a user lookup failed (e.g. invalid email), the controllers skipped password hashing, resulting in a noticeably faster response time compared to a successful lookup. Additionally, checking status flags like `is_deactivated` before verifying the password allowed enumeration of account statuses via timing.
**Learning:** In Elixir authentication, returning early from `with` statements upon failed lookups or status checks creates timing leaks. Short-circuiting must be carefully managed. When modifying `with` statements, you can extract the user lookup, inspect its result, and conditionally call `Bcrypt.no_user_verify()` to simulate the computational cost of hashing, before passing the result into the original `with` structure.
**Prevention:** Always ensure the slow password verification operation (`Bcrypt.verify_pass()`) or its dummy equivalent (`Bcrypt.no_user_verify()`) is executed *exactly once* during the authentication flow, regardless of whether the email lookup succeeds or fails. Furthermore, status checks (like `is_deactivated`) must be performed *after* the password has been successfully verified.
