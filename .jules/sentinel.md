## 2025-02-23 - [Authentication Timing Attack & User Enumeration]
**Vulnerability:** Elixir login flows used `with` statements that short-circuited on failed user lookups or checked account state flags (like `is_deactivated`) before verifying passwords. This caused rapid returns for non-existent users or allowed attackers to enumerate whether accounts were active based on response timing.
**Learning:** `Bcrypt.no_user_verify()` is necessary on paths where the user does not exist or lookup fails, to simulate hashing delay and prevent enumeration via timing attacks. Checking business logic flags (like active/inactive status) before password hashing introduces variable timing and exposes the account state.
**Prevention:** Always verify passwords before checking business status. When explicitly matching in a `case` or `with` on user lookup, ensure the catch-all/failure path invokes `Bcrypt.no_user_verify()`. Avoid short-circuiting password verification to guarantee constant-time responses for all login attempts.
