## 2024-05-03 - [User Enumeration via Timing Attack]
**Vulnerability:** Short-circuiting `with` statements in Elixir authentication flows upon a failed user lookup allowed an attacker to enumerate registered emails based on the response time. The missing password hash computation on failure resulted in a significantly faster response for invalid users. Additionally, relying on `Account.find` and short-circuiting returned `{:error, :invalid_email}` vs `{:error, :invalid}`, further aiding enumeration.
**Learning:** In Elixir, computationally expensive operations like `Bcrypt.verify_pass()` must be balanced with dummy operations (like `Bcrypt.no_user_verify()`) when a user lookup fails. The default behavior of `with` statements short-circuiting on the first non-matching clause makes them dangerous for authentication flows if the fallback clause doesn't explicitly perform the dummy delay.
**Prevention:** Avoid placing status checks (like `is_deactivated`) or skipping password checks entirely before the password verification step. Use nested `case` or `if` statements to ensure that `Bcrypt.no_user_verify()` is explicitly called on paths where the user is not found, and always return a generic error message (e.g., `{:error, :invalid}`).
