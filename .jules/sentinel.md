## 2024-05-14 - Prevent User Enumeration Timing Attacks in Authentication Flows
**Vulnerability:** User enumeration vulnerability via timing attack in `UserController.signin/2` and `SessionController.create/2`. By skipping the password hashing logic when an email was not found, the application leaked the existence of valid emails because responses for invalid emails were demonstrably faster. Furthermore, the `is_deactivated` status check occurred *before* verifying the password in `SessionController.create/2`, allowing an attacker to determine if an account is deactivated by measuring response times.
**Learning:** In Elixir, short-circuiting a `with` statement upon a failed user lookup without performing a dummy hash allows timing attacks. `Bcrypt.no_user_verify()` must be invoked during these failure paths (e.g., `nil` or `{:error, :invalid_email}`). Additionally, status checks like `is_deactivated` must occur *after* password verification (`Bcrypt.verify_pass/2`) so that all authentications (successful or failed due to incorrect password or deactivated status) take approximately the same amount of time.
**Prevention:** Ensure `Bcrypt.no_user_verify()` is called at the controller level when user lookups fail during authentication, and ensure that password hashing occurs *before* evaluating any business logic status flags.
