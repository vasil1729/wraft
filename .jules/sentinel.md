## 2024-08-12 - Prevent User Enumeration via Timing Attack in Authentication
**Vulnerability:** The application was vulnerable to user enumeration via timing attack in the standard user authentication flow (`WraftDocWeb.Api.V1.UserController.signin/2`). For non-existent users, `Account.find/1` would return `{:error, :invalid_email}`, skipping the `Bcrypt.verify_pass/2` computation entirely. This allowed an attacker to distinguish between registered and unregistered emails based on response times. Furthermore, passing specific errors down to the `FallbackController` leaked information about whether an email existed.
**Learning:** In Elixir applications utilizing `bcrypt_elixir`, the timing discrepancy between computing a hash and immediately returning an error is significant enough to permit enumeration over the network.
**Prevention:** To mitigate this, always decouple the user lookup from the `with` block's pattern matching. Perform the lookup in a separate `case` block. On wildcard matches (representing a missing user), explicitly call `Bcrypt.no_user_verify()` to simulate the time required for hashing, and map the specific error to a generic `{:error, :invalid}`. Additionally, ensure that early returns (e.g., for empty passwords mapped to `{:error, :no_data}`) use consistent generic error tuples. Avoid combining these operations in `with` blocks that implicitly bubble up specific errors like `{:error, :invalid_email}` to the `FallbackController`.
