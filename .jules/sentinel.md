## 2024-06-25 - [Timing Attack in Session Authentication]
**Vulnerability:** A timing attack vector existed in `SessionController.create/2`. Elixir `with` statements that short-circuit upon a failed user lookup, or check boolean flags (like `is_deactivated`) *before* executing the computationally expensive `Bcrypt.verify_pass/2`, allow an attacker to enumerate valid usernames or account statuses by measuring the response time.
**Learning:** Checking business logic states (e.g., deactivated user) before password verification, or skipping password verification on non-existent users, leaks sensitive state information via timing differences.
**Prevention:** Always ensure `Bcrypt.verify_pass/2` is called *before* any other status checks. If a user lookup fails, explicitly call `Bcrypt.no_user_verify()` to simulate the hashing delay and equalize response times. Prefer nested `if` statements over `with` blocks in authentication flows to guarantee the computationally expensive operation executes exactly once.
