## 2024-06-26 - Timing Attack and User Enumeration in Elixir Authentication
**Vulnerability:** The authentication flow in `WraftDocWeb.Api.V1.UserController.signin/2` was vulnerable to both a timing attack and user enumeration. If `Account.find/1` returned an error (e.g., `{:error, :invalid_email}` because the user did not exist), the `with` statement would short-circuit without verifying a password. This allowed an attacker to determine if an email exists by measuring the response time (which is much faster when no hashing occurs) and by observing the explicit error message passed to the fallback controller.
**Learning:** In Elixir authentication flows, short-circuiting `with` statements upon failed user lookups can cause timing leaks. Furthermore, specific error messages like `{:error, :invalid_email}` returned from contexts and passed through to fallback controllers can leak user existence.
**Prevention:** Always extract user lookup logic and explicitly call `Bcrypt.no_user_verify()` on failure paths to simulate password hashing delays. Additionally, map specific lookup errors (like `{:error, :invalid_email}`) to generic errors (like `{:error, :invalid}`) in the `else` block of the `with` statement or directly in the controller to prevent user enumeration via error messages.
