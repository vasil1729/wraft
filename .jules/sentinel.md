## 2024-06-24 - [Fix user enumeration timing leak in session login]
**Vulnerability:** The session login endpoint (WraftDocWeb.SessionController.create/2) suffered from a user enumeration vulnerability via a timing attack. It used a `with` statement that only called `Bcrypt.verify_pass/2` if the user existed and was active. This allowed attackers to distinguish between existing/active users and non-existent users based on response time differences.
**Learning:** In Elixir authentication flows, `with` statements can easily introduce timing leaks if the password verification is conditional on user existence. `Bcrypt.no_user_verify()` must be explicitly called when the user is not found to simulate the delay of hashing, preventing timing-based enumeration.
**Prevention:** Avoid chaining user lookup and password verification in `with` statements where failure paths omit password verification. Instead, explicitly fetch the user and use a `case` statement to ensure `Bcrypt.no_user_verify()` is called on failure paths before returning generic credential failure responses. Ensure business logic checks (like `is_deactivated`) occur *after* password verification.
