## 2024-07-20 - [Elixir Authentication Timing Attack and User Enumeration Mitigation]
**Vulnerability:** Timing attack and user enumeration vulnerability in `WraftDocWeb.Api.V1.UserController.signin/2`. A `with` statement with a user lookup (`Account.find`) followed by an authentication step (`Account.authenticate`) did not call `Bcrypt.no_user_verify()` on the lookup failure path, allowing attackers to differentiate between valid and invalid emails based on response time. Additionally, lookup failures like `{:error, :invalid_email}` were exposed and returned by the FallbackController.
**Learning:** In Elixir, placing short-circuiting user lookups inside a `with` statement alongside password verification can introduce timing leaks. You must explicitly catch failed lookups to run the hashing delay function (`Bcrypt.no_user_verify()`), and also map enumeration-revealing lookup errors (e.g. `{:error, :invalid_email}`) to generic authentication errors (e.g. `{:error, :invalid}`). Empty input fields must return `{:error, :no_data}` before lookup to preserve generic fallthroughs.
**Prevention:** Always extract user lookups in authentication flows out of the `with` statement and into a defensive `case` block. In the `_ ->` catch-all branch, explicitly invoke `Bcrypt.no_user_verify()` and translate the error to `{:error, :invalid}`. Finally, pass the sanitized result of this block back into the `with` statement.
