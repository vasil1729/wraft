## 2024-05-24 - [Fix User Enumeration and Timing Attacks]
**Vulnerability:** Elixir authentication flows often use `with` statements that handle both user lookup and password verification. Returning early on failed lookups, or returning specific lookup error tuples (like `{:error, :invalid_email}`), allows attackers to enumerate registered emails based on either specific HTTP responses or variations in response time. Additionally, password reset endpoints that perform early returns upon failing to find an email are also subject to enumeration attacks.
**Learning:** In Elixir, implicit error fallthrough in `with` statements paired with generic fallback controllers can be dangerous if specific errors like `{:error, :invalid_email}` are mapped to highly specific error messages. Moreover, the lack of a constant-time hashing dummy operation (`Bcrypt.no_user_verify()`) on failure paths leaks the existence of users via timing variations, since password verification takes significantly longer than user lookups.
**Prevention:** To prevent user enumeration and timing attacks, user lookups in authentication endpoints must be isolated in `case` statements to safely inject `Bcrypt.no_user_verify()` upon lookup failure. Furthermore, specific lookup error messages must be sanitized and mapped to generic failure messages (like `{:error, :invalid}`) before reaching the fallback controller, or the endpoints must be rewritten to always return a generic success message (such as in password resets).
