## 2024-07-05 - Fix timing attacks and user enumeration in Authentication and Password Reset flows
**Vulnerability:** Timing attacks and user enumeration existed in the login and password reset endpoints. Invalid login emails were leaking their status due to missing hash delays, and missing `Bcrypt.no_user_verify()` allowed timing enumeration. The password reset flow was vulnerable to user enumeration via conditional success messages.
**Learning:** In Elixir `with` statements, early short-circuiting on `nil` or `{:error, ...}` lookups completely skips the password hash verification step, leaking user existence via timing differences. Also, never use `Bcrypt.no_user_verify()` on the unhappy path of a password reset flow because the happy path does not verify a password, introducing a severe CPU-exhaustion DoS vulnerability.
**Prevention:** Explicitly use `case` to extract user lookups and safely inject `Bcrypt.no_user_verify()` before returning generic errors like `{:error, :invalid}` for login flows. For password reset flows, always return a generic success message on failure without injecting `Bcrypt.no_user_verify()`.
