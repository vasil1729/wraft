## 2024-05-24 - [Timing Attacks in Elixir `with` statements]
**Vulnerability:** A vulnerability to timing attacks and user/status enumeration due to missing `Bcrypt.no_user_verify()` calls on missing user paths, and incorrect short-circuiting of `with` statements before checking passwords.
**Learning:** In Elixir, `with` statements that short-circuit on initial user lookups or status checks (like `is_deactivated`) without simulating password verification times leak information. This is particularly problematic in auth flows. Additionally, returning exact error tuples like `{:error, :invalid_email}` leaks whether a specific email is registered.
**Prevention:** Always ensure the slow password verification path takes approximately the same amount of time regardless of whether a user exists or not by explicitly calling `Bcrypt.no_user_verify()` on the unhappy lookup path. Perform password verification *before* checking business logic status flags. Map specific error tuples to generic ones (like `{:error, :invalid}`) to prevent enumeration.
