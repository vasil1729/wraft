## 2024-08-23 - Prevent User Enumeration and Timing Attacks in Elixir with Statements
**Vulnerability:** The authentication flow used an Elixir `with` statement directly on the result of `Account.find(email)`. Since `Account.find` returns `{:error, :invalid_email}` when a user isn't found, the `with` statement short-circuited and bypassed `Account.authenticate` completely. This created a timing attack vulnerability because non-existent users were processed faster (no Bcrypt hash verification), and the `{:error, :invalid_email}` tuple leaked through the `FallbackController` to explicitly confirm the email did not exist.
**Learning:** In Elixir `with` statements used for authentication, short-circuiting on user lookup failures prevents the hash verification step, leading to timing discrepancies. Furthermore, returning specific error tuples (like `{:error, :invalid_email}`) instead of generic ones (like `{:error, :invalid}`) allows attackers to enumerate users based on the HTTP response.
**Prevention:** Extract the user lookup out of the `with` statement into an explicit `case` statement. In the failure path (`_ ->`), explicitly call `Bcrypt.no_user_verify()` to simulate the timing of a password hash verification, and remap the error to a generic `{:error, :invalid}`. Additionally, add an explicit `else` block to the `with` statement to ensure any unexpected errors are also mapped to `{:error, :invalid}`.
