## 2024-05-18 - Timing Attack and User Enumeration in Authentication Flows
**Vulnerability:** The `signin/2` function in `UserController` and `create/2` function in `SessionController` were vulnerable to timing attacks and user enumeration. If an invalid email was provided, the functions returned early without executing `Bcrypt.verify_pass()`. This timing difference allowed attackers to enumerate valid email addresses.
**Learning:** In Elixir authentication flows using `bcrypt_elixir`, you must always simulate the hashing delay for non-existent users using `Bcrypt.no_user_verify()` to prevent timing attacks. Additionally, returning specific errors like `{:error, :invalid_email}` allows attackers to enumerate users if those errors are mapped to distinct messages or behaviors.
**Prevention:** Always extract the user lookup into a `case` statement. In the failure path (e.g., `_ ->`), call `Bcrypt.no_user_verify()` and map the specific error to a generic one (e.g., `{:error, :invalid}`). Also, handle edge cases like missing or empty passwords before the user lookup and return a generic error (e.g., `{:error, :no_data}`) consistently.
