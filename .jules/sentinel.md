## 2024-05-24 - [Fix Status Enumeration and Timing Attacks in Authentication]
**Vulnerability:** Timing attacks leading to user and status enumeration were present in the `SessionController` and `UserController` authentication methods. Specifically, `is_deactivated` flag was checked before password verification, allowing status enumeration, and `with` statements short-circuited upon failed user lookups without simulating password hashing time, allowing email enumeration via timing attacks.
**Learning:** In Elixir, authentication flow must always verify the user's password (`Bcrypt.verify_pass`) before checking business logic status flags like `is_deactivated`. Placing status checks before password verification introduces a timing attack vector that allows enumeration of account statuses. Also, short-circuiting `with` statements upon failed user lookups can cause timing leaks; explicitly call `Bcrypt.no_user_verify()` on these specific failure paths (e.g., `nil` or `{:error, :invalid_email}`) to simulate password hashing delays. Do not call it if password verification fails, to avoid double-hashing vulnerabilities.
**Prevention:** Always structure authentication to unconditionally verify the password hash using `Bcrypt.verify_pass/2` or `Bcrypt.no_user_verify()` before evaluating user-specific status flags. Extract user lookups from `with` statements to conditionally execute `Bcrypt.no_user_verify()` if the lookup fails, simulating a generic delay and preventing enumeration.
