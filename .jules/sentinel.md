## 2025-01-22 - Prevent Enumeration & DoS in Elixir Auth Flows
**Vulnerability:** The `signin` and `generate_token` actions in `UserController` allowed user enumeration. `signin` suffered from a timing attack because missing users didn't trigger `Bcrypt.verify_pass`. `generate_token` returned errors for non-existent emails, allowing attackers to check which emails are registered.
**Learning:** Preventing timing attacks by forcing a password hash simulation (`Bcrypt.no_user_verify()`) should only be done on login paths, not password reset paths. If `no_user_verify()` is used in `generate_token` (password reset), it introduces a severe CPU exhaustion DoS vulnerability since the happy path for reset doesn't hash a password.
**Prevention:** In `signin`, always evaluate `Bcrypt.no_user_verify()` if the user lookup fails, and map specific lookup errors (e.g., `{:error, :invalid_email}`) to generic errors (`{:error, :invalid}`). In password reset flows (`generate_token`), always return a generic 200 OK success message regardless of whether the email exists, and strictly *avoid* `no_user_verify()`.
