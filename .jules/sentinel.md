## 2024-08-25 - Prevent Timing Attack & User Enumeration in Auth Flow
**Vulnerability:** The authentication flow in `UserController.signin/2` performs user lookup via `Account.find/1` and returns early or skips password hashing via `Account.authenticate/1` if the user is not found, leading to a timing attack that leaks user existence. Additionally, error structures are not normalized, enabling user enumeration.
**Learning:** Returning early or structuring `with` statements without executing `Bcrypt.no_user_verify()` for unknown users creates a timing discrepancy compared to existing users where `Bcrypt.verify_pass/2` is called. Moreover, failing to map specific missing-user errors to generic invalid-credentials errors allows attackers to enumerate users by distinguishing between response times or payloads.
**Prevention:** Extract user lookups into a defensive `case` block before the main `with` statement. In the failure path for the lookup, explicitly call `Bcrypt.no_user_verify()` to simulate the hash calculation time, and map any lookup errors to generic `{:error, :invalid}`. Ensure empty passwords are handled before the user lookup with consistent generic errors like `{:error, :no_data}`.
