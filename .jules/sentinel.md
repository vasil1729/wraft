## 2026-05-20 - Fix Timing Attack and Account Enumeration Vulnerabilities in Authentication
**Vulnerability:** Timing attacks allowing user enumeration in `SessionController.create` and `UserController.signin` due to short-circuiting on failed email lookups before checking passwords, and account status enumeration due to checking account flags (`is_deactivated`) prior to verifying user passwords. Additionally, user enumeration vulnerability in `UserController.generate_token` due to leaking email existence.
**Learning:** In Elixir, early exits from `with` statements on failed database lookups create timing discrepancies because the expensive `Bcrypt.verify_pass` operation is skipped. To prevent enumeration, the code must simulate this timing with `Bcrypt.no_user_verify()` when the user isn't found. Furthermore, all access control and status checks (like `is_deactivated`) MUST occur *after* the password is successfully verified; otherwise, an attacker can enumerate which accounts exist and are deactivated without knowing their passwords. Finally, in "fire-and-forget" flows like password reset generation, we must always return a generic success message to prevent user enumeration, but we MUST NOT use `Bcrypt.no_user_verify()` on the unhappy path as it creates a CPU-exhaustion DoS vector (since the happy path only does a DB lookup and enqueues an email).
**Prevention:**
1. For authentication flows (login): Extract user lookups, check for `nil` or error, and explicitly call `Bcrypt.no_user_verify()` to simulate hashing time on failure before continuing the flow or returning a generic error.
2. For authentication flows (login): Always verify the user's password (`Bcrypt.verify_pass`) *before* checking any business logic flags like `is_deactivated`.
3. For asynchronous flows (password reset): Always return a standardized 200 OK generic success message regardless of whether the email exists. Do not introduce artificial hashing delays (`Bcrypt.no_user_verify()`) on failure if the happy path does not verify a password, as this creates a DoS vulnerability.
