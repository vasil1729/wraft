## 2024-05-24 - Fix User Enumeration and Timing Attacks in Auth Flow
**Vulnerability:** The `signin/2` function in `WraftDocWeb.Api.V1.UserController` leaks user existence via timing differences (calling `Bcrypt.verify_pass/2` only for existing users) and distinct error messages (returning `{:error, :invalid_email}` vs `{:error, :invalid}`). Empty password checks also allowed enumeration if not consistently handled before lookup.
**Learning:** Elixir authentication flows must separate user lookup into a `case` statement, calling `Bcrypt.no_user_verify()` in the catch-all branch. Empty password validation must occur before lookup to return identical generic errors (`{:error, :no_data}`).
**Prevention:** Use defensive input validation (e.g., `Map.get(params, "key")`) before lookup, normalize all failures to a generic error (e.g., `{:error, :invalid}`) in an explicit `else` block within the `with` statement, and prevent timing discrepancies by ensuring Bcrypt runs unconditionally.
