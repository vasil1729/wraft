## 2024-05-24 - [CRITICAL] Stop User Enumeration via Timing Attacks and Error Fallthrough
**Vulnerability:** User enumeration vulnerability through error messages (`No user with this email.!` triggered by `FallbackController`) and timing attacks (lack of bcrypt hashing for invalid users in `with` block).
**Learning:** In Elixir APIs using `FallbackController`, a `with` statement checking a user's existence (`Account.find/1`) and immediately returning `{:error, :invalid_email}` implicitly leaks to the user. Additionally, placing password verification *only* within the `with` block happy path means an invalid user check returns instantly, creating a timing attack vulnerability.
**Prevention:** Always extract user lookup into a defensive `case` statement. In the wildcard failure path, trigger `Bcrypt.no_user_verify()` to simulate hashing time, and explicitly remap enumeration errors (like `{:error, :invalid_email}`) to a generic error (like `{:error, :invalid}`) before returning, preventing info leaks via `FallbackController`.
