## 2024-06-22 - [Timing Attack and User Enumeration in signin]
**Vulnerability:** User enumeration and timing attack vulnerability in `WraftDocWeb.Api.V1.UserController.signin/2`. The `with` statement immediately exits when `Account.find/1` fails, returning an `{:error, :invalid_email}` which leaks the fact that a user does not exist via the `FallbackController`. It also skips `Bcrypt.verify_pass/2`, causing requests for non-existent users to return significantly faster than for existing users.
**Learning:** In Elixir authentication flows, short-circuiting `with` statements upon failed user lookups can cause timing leaks. Also, returning specific errors like `{:error, :invalid_email}` allows attackers to enumerate registered emails.
**Prevention:** Explicitly call `Bcrypt.no_user_verify()` on failure paths (e.g., `nil` or `{:error, :invalid_email}`) before evaluating passwords to simulate password hashing delays, ensuring it's invoked exactly once. Furthermore, map specific lookup errors to generic errors like `{:error, :invalid}` to prevent user enumeration.
