## 2024-07-01 - [Timing Attacks and User Enumeration in Auth Flows]
**Vulnerability:** User lookup processes inside authentication flows (like `signin` in `UserController` and `create` in `SessionController`) failed to call `Bcrypt.no_user_verify()` on unsuccessful lookups before exiting, making the application vulnerable to timing attacks that allow an attacker to enumerate valid users. Additionally, specific error tuples like `{:error, :invalid_email}` were leaking email existence through the `FallbackController`.
**Learning:** In Elixir, placing `with` statements that perform a user lookup and password verification sequentially creates a timing attack vulnerability if the user lookup fails and the password verification is skipped. You must explicitly separate the execution path and simulate the hashing delay using `Bcrypt.no_user_verify/0` on failure paths without evaluating the password.
**Prevention:** To prevent user enumeration and timing attacks, always extract user lookups from `with` statements, conditionally inject `Bcrypt.no_user_verify()` on failure paths (such as `nil` or `{:error, :invalid_email}`), and map any specific lookup errors to generic errors (like `{:error, :invalid}`) before returning them or passing them to the fallback controller.
