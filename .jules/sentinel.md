## 2024-06-01 - User Enumeration via Timing Attacks in Login Flow
**Vulnerability:** Elixir authentication endpoints (`SessionController.create/2` and `UserController.signin/2`) allowed user enumeration through timing attacks. This occurred because missing users or missing specific attributes bypassed the expensive `Bcrypt.verify_pass/2` computation, failing fast and allowing an attacker to determine if an email or specific user state exists based on response times.
**Learning:** In Elixir `with` statements, early short-circuiting on user lookups or user attribute checks without executing a dummy password hash on the failure path creates observable timing discrepancies.
**Prevention:** Always use a defensive check with `Bcrypt.no_user_verify()` on user lookup failures. Ensure that the expensive operation (`Bcrypt.verify_pass/2`) is consistently executed before evaluating other business logic state (like `is_deactivated`), ensuring a uniform time profile for authentication attempts.
