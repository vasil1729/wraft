## 2024-07-23 - [User Enumeration / Timing Attack in Authentication Flow]
**Vulnerability:** The Elixir authentication flow in `UserController.signin/2` performs user lookups via `Account.find/1` directly inside a `with` statement. If the user does not exist, `Account.find/1` returns `{:error, :invalid_email}` and bypasses the slow `Bcrypt.verify_pass/2` logic (inside `Account.authenticate`). This discrepancy in response time and exact error tuple allows an attacker to enumerate valid email addresses based on timing analysis and differing generic error messages.
**Learning:** `with` statements can silently short-circuit and introduce timing vulnerabilities when error paths avoid costly cryptographic hashing. Elixir relies heavily on pattern matching, requiring explicit catch-alls to ensure `Bcrypt.no_user_verify()` executes for non-existent users before passing control back to the `with` block or falling through to the `FallbackController`.
**Prevention:** Always extract user lookups (e.g., `Account.find/1`) from `with` block pipelines. Use a defensive `case` block to catch wildcard failure paths (`_ ->`), unconditionally trigger `Bcrypt.no_user_verify()`, and map the specific failed lookup error to a generic tuple like `{:error, :invalid}`.
