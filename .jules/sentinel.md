## 2024-07-12 - Prevent Timing and User Enumeration Vulnerability in Authentication
**Vulnerability:** The API login endpoint failed to simulate password hashing delays when an email lookup failed, creating a timing side-channel that allowed user enumeration. It also allowed implicit error fallthrough to `FallbackController`, exposing the specific `{:error, :invalid_email}` tuple as "No user with this email.!".
**Learning:** In Elixir `with` statements, placing status checks or lookups before password verification without explicit failure handling allows timing attacks. `Bcrypt.no_user_verify()` must be explicitly called on the failure path, and specific lookup errors must be mapped to generic credential errors in the `else` block to prevent information disclosure.
**Prevention:** Extract the user lookup into a `case` statement, unconditionally inject `Bcrypt.no_user_verify()` on failure, and map explicit errors (like `{:error, :invalid_email}`) to generic errors (like `{:error, :invalid}`) in the surrounding `with` block to avoid exposing internal state via the `FallbackController`.
