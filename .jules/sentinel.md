## 2024-05-24 - [User Enumeration via Timing Disparity in Elixir Authentication]
**Vulnerability:** User enumeration timing attack vulnerability existed in the authentication flow because the application evaluated `Bcrypt.verify_pass/2` only when the requested user existed. For non-existent users, the request would fail fast due to early return, revealing whether the email/username is registered.
**Learning:** In Elixir `with` statements, placing slow password hashing operations conditionally on the user existing allows attackers to enumerate users by measuring response times. Returning specific errors like `{:error, :invalid_email}` also exposes user existence via error mapping in the fallback controller.
**Prevention:** Always extract the user lookup into a `case` block before any `with` statements. In the wildcard failure path (`_ ->`), explicitly call `Bcrypt.no_user_verify()` to simulate the timing of a real password check. Additionally, map specific lookup errors directly to generic errors like `{:error, :invalid}` to avoid exposing state through response bodies.
