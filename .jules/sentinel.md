## 2024-05-23 - User Enumeration via Timing Attacks
**Vulnerability:** The application was vulnerable to user enumeration via timing attacks in `SessionController` and `UserController`. In both controllers, the password verification (`Bcrypt.verify_pass/2`) was skipped if the user lookup failed or if the user account status was checked first. Also, `UserController` leaked whether emails existed by returning different responses in password reset flows and explicit error tuples in login flows.
**Learning:** In Elixir authentication flows, short-circuiting `with` statements upon failed user lookups can cause timing leaks. Furthermore, placing status checks (like `is_deactivated`) before password verification allows enumeration of account statuses via timing attacks. To prevent enumeration in password reset flows, always return a generic success message.
**Prevention:** Explicitly call `Bcrypt.no_user_verify()` on failure paths (e.g., `nil` or `{:error, :invalid_email}`) to simulate password hashing delays. Verify the user's password (`Bcrypt.verify_pass`) before checking business logic status flags. Return standardized, generic messages (e.g., `{:error, :invalid}` or generic flash messages) instead of specific responses. Never use `Bcrypt.no_user_verify()` on the unhappy path of a password reset flow due to DoS risks.
