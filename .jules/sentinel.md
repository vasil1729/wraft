## 2024-08-08 - Fixing Timing Attack and User Enumeration in Elixir Authentication Flow
**Vulnerability:** A timing attack and user enumeration vulnerability existed in the login flow. If a user didn't exist, the `Bcrypt.verify_pass` function wasn't executed, allowing an attacker to determine if a username existed by measuring the response time.
**Learning:** In Elixir authentication flows using `bcrypt_elixir`, you need to call `Bcrypt.no_user_verify()` for non-existent users to ensure that the response time is consistent, masking whether the user lookup succeeded or failed. Also, the failure needs to be mapped to a generic error (`{:error, :invalid}`) to prevent the `FallbackController` from leaking user existence via a specific error message.
**Prevention:** Always verify password hashes for non-existent users using a dummy hash comparison function like `Bcrypt.no_user_verify()`. Extract user lookups from `with` statements into a `case` block to reliably handle the missing user case and map it to a generic error to preserve the implicit error fallthrough for the `FallbackController`.
