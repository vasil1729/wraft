## 2024-05-15 - User Enumeration Timing Attack
**Vulnerability:** The application was vulnerable to timing attacks when verifying passwords because it immediately returned on invalid users without hashing any password, allowing attackers to check if a user existed by looking at response times.
**Learning:** Always use `Bcrypt.no_user_verify()` for unknown or invalid users instead of failing immediately. In Elixir, always map specific failed user lookups (`{:error, :invalid_email}`) to a generic error `{:error, :invalid}` before continuing so it doesn't bypass `FallbackController` generic error responses, avoiding simple string enumeration.
**Prevention:** Separate user lookup in a `case` statement, mapping failed lookups to `nil`. In the subsequent `with` block, use an explicit `if/else` block based on the user presence to execute `Bcrypt.no_user_verify()` or `Bcrypt.verify_pass/2`, returning exactly `{:error, :invalid}` for both failure paths to equalize response times and errors.
