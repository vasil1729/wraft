## 2024-05-22 - Authentication Timing Attack and Enumeration Prevention
**Vulnerability:** User and status enumeration was possible via timing attacks because failed user lookups short-circuited authentication logic before password verification, making invalid emails return faster. Status checks (`is_deactivated`) before password verification also allowed enumeration of account states. Furthermore, returning specific error tuples (like `{:error, :invalid_email}`) allowed enumeration via explicit error messages.
**Learning:** In Elixir, explicit simulation of password hashing via `Bcrypt.no_user_verify()` is critical on failed lookup paths (e.g., when the user doesn't exist). Password verification must happen *before* checking business logic status flags. Controller error messages must remain generic (e.g., `{:error, :invalid}`).
**Prevention:** Always structure authentication `with` blocks or handlers to extract user lookup, unconditionally simulate hashing if it fails, and verify the password before verifying account status. Always return generic failure messages.
