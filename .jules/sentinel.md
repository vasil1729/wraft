## 2024-05-24 - User Enumeration via Timing Attacks in Elixir with statements
**Vulnerability:** User enumeration timing attack where a missing user (email) bypassed `Bcrypt.verify_pass()`, causing faster responses than valid user emails. Additionally, business logic status checks (`is_deactivated`) were performed before password verification in a `with` statement, allowing enumeration of account statuses via timing or short-circuited error logic.
**Learning:** In Elixir, `with` statements naturally short-circuit on mismatches. When authenticating users, if a user lookup fails or returns `nil`, we must still simulate the CPU time of `Bcrypt.verify_pass` by explicitly calling `Bcrypt.no_user_verify()`. The error state (`{:error, :invalid_email}`) must be safely mapped to a generic `{:error, :invalid}` for the FallbackController to prevent error message leakage. Furthermore, status checks (like `is_deactivated`) must be done *after* the password check to prevent timing leaks of those statuses.
**Prevention:** Always extract user lookup from `with` statements if `Bcrypt.verify_pass` happens downstream. If the lookup fails, invoke `Bcrypt.no_user_verify()`. Map specific lookup errors to generic errors. Always verify passwords before checking account status flags.
