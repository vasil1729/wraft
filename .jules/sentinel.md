## 2025-02-14 - [User Enumeration and Timing Attack via Login Fallthrough]
**Vulnerability:** A logic error in the API signin flow (`UserController.signin`) permitted implicit fallthrough of missing user lookup errors (e.g., `{:error, :invalid_email}`) directly to `FallbackController`. This caused the server to return specific responses ("No user with this email.!") instead of a generic credential failure ("Your email-password combination doesn't match. Please try again.!"). Furthermore, bypassing `Bcrypt.verify_pass/2` when the user did not exist resulted in significantly faster response times for invalid emails compared to valid emails, which can be observed as a timing attack to confirm a user's presence.
**Learning:** In Elixir `with` statements used in authentication pipelines, failed initial user lookups (e.g. `Account.find/1`) returning errors will bypass all subsequent steps unless specifically handled. Relying purely on implicit error fallthrough to `FallbackController` causes specific internal errors (like `:invalid_email`) to be directly exposed to clients.
**Prevention:** Always intercept authentication user lookup failures before they enter the main `with` statement. Use a `case` statement to handle lookups: explicitly returning the user on success, and on failure, invoking a timing-safe function (like `Bcrypt.no_user_verify()`) followed by a safe, generic error return like `{:error, :invalid}`.
