## 2024-06-23 - Prevent timing and error message user enumeration in authentication flows
**Vulnerability:** The Elixir authentication flows (both admin session and user API) leaked user existence via timing differences and specific error messages. The `with` statement short-circuited on invalid emails, skipping the expensive password hashing process. Furthermore, `WraftDocWeb.FallbackController` rendered `{:error, :invalid_email}` directly as "No user with this email!", explicitly allowing enumeration.
**Learning:** In Elixir, placing user existence checks and password verifications sequentially in a `with` statement creates a critical timing attack vector. Attackers can enumerate users by measuring response times. Additionally, falling back to specific controller error messages leaks sensitive information.
**Prevention:** Always extract user lookup operations outside the main authentication `with` block. Use a `case` statement to conditionally invoke `Bcrypt.no_user_verify()` when the user is not found, ensuring a constant execution time. Remap specific error tuples like `{:error, :invalid_email}` to generic credentials failures (e.g., `{:error, :invalid}`) before returning them from the controller.
