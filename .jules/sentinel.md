## 2026-08-04 - Fixed User Enumeration via Timing Attack
**Vulnerability:** The login flow in `user_controller.ex` was vulnerable to user enumeration via timing attacks. When an invalid email was provided, the code failed early without hashing the password, making requests with invalid emails significantly faster than requests with valid emails.
**Learning:** In Elixir with `Bcrypt`, to properly prevent timing attacks, the slow hashing operation (e.g., `Bcrypt.verify_pass/2` or `Bcrypt.no_user_verify/0`) must be executed exactly once regardless of whether the user exists or not. Additionally, replacing specific lookup errors (like `{:error, :invalid_email}`) with generic ones (`{:error, :invalid}`) is required so the `FallbackController` doesn't leak existence information via generic messages.
**Prevention:** Extract user lookups into a `case` statement. If the user isn't found, execute `Bcrypt.no_user_verify()` and map the error to a generic `{:error, :invalid}`. Keep the extracted logic out of short-circuiting structures like `with` until the dummy hash is guaranteed to run. Ensure early exits for missing parameters (e.g. empty password) happen before user lookup to avoid conditional generic messages.
