## 2024-03-24 - [Fix user enumeration timing attacks and DoS vectors]
**Vulnerability:** User enumeration timing attacks existed in `SessionController` and `UserController` because an early exit on `Account.find` (when an email is not found) skipped the slow `Bcrypt.verify_pass` operation. Additionally, `SessionController` checked `is_deactivated` before hashing the password, allowing enumeration of deactivated accounts via timing. Finally, the `generate_token` password reset flow had a DoS vector if `Bcrypt.no_user_verify` were inappropriately used on the unhappy path.
**Learning:** In Elixir authentication flows, always ensure the slow password hashing operation runs exactly once. When an email is not found, simulate the delay using `Bcrypt.no_user_verify()`. However, do NOT use `no_user_verify()` on password reset flows that do not normally require password hashing (like sending an email token), as this introduces a CPU-exhaustion DoS attack vector. Also, always verify passwords before checking account status flags like `is_deactivated`.
**Prevention:** Avoid short-circuiting `with` statements before password hashing. Extract the user lookup and use a `case` statement to invoke `no_user_verify()` if the user is missing. Always place `Bcrypt.verify_pass/2` before any business logic checks.
