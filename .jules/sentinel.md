## 2024-08-27 - [Auth Timing Attack Prevention]
**Vulnerability:** User enumeration is possible via timing attacks during the authentication flow (`signin/2` in `user_controller.ex`). The `with` statement immediately evaluates `Account.authenticate` only if the user is found, resulting in a timing discrepancy if a non-existent email is provided (since `Bcrypt.verify_pass` is skipped).
**Learning:** In Elixir, using a `with` statement for authentication that evaluates password hashing only when a user lookup succeeds exposes the application to timing attacks. Relying on an `else` block to execute `Bcrypt.no_user_verify/0` is problematic since other clauses in the `with` might fail, complicating the error path and potentially breaking implicit FallbackController routing.
**Prevention:** Always isolate the user lookup into an explicit `case` block before the `with` statement. In the failure path (`_ ->`), execute `Bcrypt.no_user_verify/0` to guarantee consistent execution time, and explicitly remap specific lookup errors (like `{:error, :invalid_email}`) to generic errors (`{:error, :invalid}`) to prevent user enumeration while preserving normal FallbackController behavior.
