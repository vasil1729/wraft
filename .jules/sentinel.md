## 2025-01-20 - [Authentication Timing Attacks and Enumeration]
**Vulnerability:** Timing attacks and user/status enumeration in Elixir authentication flows (`UserController` and `SessionController`). The `with` statements exited early on missing users or deactivated statuses before performing the slow `Bcrypt.verify_pass/2` operation, and leaked error tuples like `{:error, :invalid_email}` to the FallbackController.
**Learning:** In Elixir, `with` statements can inadvertently create timing side-channels if slow operations are conditionally executed. Furthermore, returning specific error tuples (like `{:error, :invalid_email}`) allows attackers to enumerate registered users via different response times or generic flash messages.
**Prevention:** Always extract user lookups to an explicit `case` statement and inject `Bcrypt.no_user_verify()` on the failure path to normalize response times. Perform status checks (e.g., `is_deactivated`) *after* verifying passwords, and map specific lookup error tuples to generic error responses (`{:error, :invalid}`) in the `else` block of `with` statements.
