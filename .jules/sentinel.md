## 2026-07-16 - Timing Attack and Error Message User Enumeration in Auth
**Vulnerability:** User enumeration is possible on the login API (`signin/2` in `UserController`). If a user doesn't exist, the `Account.find/1` returns an error (which ultimately falls through as `{:error, :invalid_email}`) which explicitly tells an attacker the user does not exist. Furthermore, it completely bypasses the bcrypt password verification, causing requests for non-existent users to return much faster than those for existent users (timing attack).
**Learning:** `with` statements in Elixir that chain user lookup and password verification can easily leak timing data if the lookup fails early. Furthermore, the `FallbackController` blindly proxies specific application logic errors (like `:invalid_email`) to the user, breaking generic credential failure responses.
**Prevention:** Extract the user lookup out of the `with` statement into a defensive `case` block. On the failure path (`_ ->`), explicitly invoke `Bcrypt.no_user_verify()` to simulate hashing time, and map the specific lookup error to a generic `{:error, :invalid}` so the FallbackController provides a generic error response, thwarting both timing and message enumeration.
