## 2024-06-25 - [Prevent User Enumeration Timing Attack]
**Vulnerability:** User enumeration timing attack vulnerability in `WraftDocWeb.Api.V1.UserController.signin/2`. A `with` statement immediately checked for the user's existence and if the user did not exist, it short-circuited and did not perform the expensive `Bcrypt.verify_pass/2` computation, leading to a noticeable timing difference between valid and invalid emails.
**Learning:** In Elixir authentication flows, conditionally checking a password only when a user is found introduces a timing vulnerability. When a user lookup fails, we must explicitly perform a dummy hash operation using `Bcrypt.no_user_verify()` to balance the response time, preventing attackers from brute-forcing valid email addresses. Using a `with` statement directly with the lookup can break the FallbackController's ability to normalize generic generic error responses if not handled carefully.
**Prevention:** Always extract user lookup into a defensive `case` block before `with`. In the wildcard failure path `_ ->`, trigger `Bcrypt.no_user_verify()` and map specific errors to generic ones (like `{:error, :invalid}`). Provide an explicit `else` block `_ -> {:error, :invalid}` for the `with` statement to guarantee unified error responses.
