## 2024-05-24 - [User Enumeration / Timing Attack via Password Hash Missing Path]
**Vulnerability:** The `signin` endpoint returned different timing responses depending on whether the user existed. If a user was found, it took longer to respond due to password verification (`Bcrypt.verify_pass`). Additionally, `Account.find` could fail to find the email, skipping the bcrypt process in the `with` statement, which opens up user enumeration.
**Learning:** In Elixir, using a `with` statement that chains user lookup and password verification inherently creates a timing discrepancy if the user lookup fails (e.g. `{:error, :invalid_email}`), as the password verification logic is skipped. FallbackController then uses `{:error, :invalid_email}` to explicitly inform attackers that the user doesn't exist.
**Prevention:** Extract the user lookup out of the `with` statement into a defensive `case` block. On failure paths, always call `Bcrypt.no_user_verify()` to balance the timing, and strictly map all lookup failures to a generic `{:error, :invalid}` tuple to maintain a secure and consistent FallbackController error response.
