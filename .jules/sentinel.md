## 2024-05-24 - [Timing Attacks and User Enumeration in Auth Flows]
**Vulnerability:** User enumeration was possible via timing attacks in Elixir authentication flows where `Bcrypt.verify_pass` was skipped if an email lookup failed. Additionally, `SessionController` checked `is_deactivated` before `verify_pass`, leaking user deactivation status via timing differences.
**Learning:** In Elixir, missing `Bcrypt.no_user_verify()` calls on missing user lookups allow timing-based enumeration. Furthermore, checking business logic flags (like deactivation) before password verification creates timing attacks that leak those flags.
**Prevention:** Always implement `Bcrypt.no_user_verify()` on the explicit failure path of a user lookup during sign-in. Crucially, always perform `Bcrypt.verify_pass` *before* checking business logic status flags in a `with` statement. Do not use `Bcrypt.no_user_verify()` on password reset unhappy paths to avoid CPU-exhaustion DoS vulnerabilities.
