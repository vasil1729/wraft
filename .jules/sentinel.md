## 2024-06-20 - Prevent User Enumeration and Timing Attacks in Auth Flows
**Vulnerability:** In Elixir login flows using `with` statements, checking business logic flags (like `is_deactivated`) before password verification (`Bcrypt.verify_pass/2`), or blindly relying on `with` to short-circuit upon user lookup failure, introduces a severe timing attack vulnerability. This allows attackers to enumerate valid email addresses and even discover account status flags (like deactivated accounts) based on response times because the expensive password hashing operation is skipped for invalid emails or deactivated users.
**Learning:** `Bcrypt.verify_pass/2` expects a binary string. Attempting to run it when the user is `nil` crashes the application. Thus, `Bcrypt.no_user_verify/0` must be used to mitigate timing attacks by simulating a hashing delay when a user doesn't exist. Furthermore, to avoid double-hash DoS vulnerabilities, the execution path for existing vs non-existing users must be completely separated using a `case` block on the fetched user object. Status checks must happen *after* password verification.
**Prevention:** Always structure authentication flows using `case` or `if/else` logic that guarantees a bcrypt hash operation occurs exactly once per login attempt, regardless of whether the user exists, is deactivated, or provided the wrong password. Map specific lookup errors to generic errors before returning to prevent enumeration.
