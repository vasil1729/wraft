## 2024-05-24 - Elixir Authentication Timing Attacks
**Vulnerability:** In Elixir authentication flows, conditionally skipping `Bcrypt.verify_pass/2` when user lookups fail creates a significant timing difference (fast-fail vs. slow-hash), enabling user enumeration via timing attacks. Additionally, checking business logic flags (like `is_deactivated`) before password verification also exposes account statuses to enumeration.
**Learning:** `Bcrypt.no_user_verify/0` must be used to simulate the hashing delay precisely on failure paths (e.g., non-existent user). However, it must NOT be used unconditionally or redundantly (e.g., inside the `else` block of a `with` statement that also evaluates the password), as this could trigger a double-hash DOS vector if the user exists but the password verification fails.
**Prevention:** Separate the user lookup from password verification using a `case` statement to inject `Bcrypt.no_user_verify()` solely on the lookup failure path. Pass the result into the main authentication flow, ensuring `Bcrypt.verify_pass/2` is evaluated immediately before any business logic checks (like `is_deactivated`).
