## 2024-06-03 - [User Enumeration and Timing Attacks in Auth Flows]
**Vulnerability:** Elixir authentication flows in `WraftDocWeb.SessionController` and `WraftDocWeb.Api.V1.UserController` were susceptible to timing attacks and user enumeration. If a user lookup failed (e.g., wrong email), the request would exit earlier without verifying the password, meaning requests with invalid emails returned much faster than those with valid emails.
**Learning:** Using `with` statements without explicitly handling lookup failures (`nil` or `{:error, _}`) causes short-circuiting. The time differential (simulating bcrypt hashing vs immediately returning) exposes whether an email address is registered in the system. Further, checking flags like `user.is_deactivated` before `Bcrypt.verify_pass/2` allows attackers to enumerate active vs deactivated accounts.
**Prevention:** Always extract user lookups in auth flows and conditionally invoke `Bcrypt.no_user_verify()` on failure paths to simulate hashing delays. Map all lookup and password failures to a generic error like `{:error, :invalid}`. Ensure `Bcrypt.verify_pass/2` occurs before checking any business logic status flags.
