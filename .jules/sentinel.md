## 2024-05-24 - Fix User Enumeration and Timing Attack in User Sign-in
**Vulnerability:** User sign-in flows using `with` statements without executing `Bcrypt.no_user_verify()` on failure paths allow user enumeration through timing attacks. Attackers can distinguish existing vs non-existing emails based on response time. Additionally, invalid emails mapped directly to `FallbackController` leak error tuples or explicit error messages about user existence.
**Learning:** `with` statement fallthrough logic can bypass intended timing delays if not handled explicitly. Empty input conditions shouldn't be handled by pattern matching, as missing keys can fail entirely.
**Prevention:** Separate user lookup in sign-in flows using `case` statements. Handle empty inputs first to prevent early returns that leak state. Ensure wildcard catches (`_ ->`) execute `Bcrypt.no_user_verify()` and always remap internal errors (like `{:error, :invalid_email}`) to generic responses (like `{:error, :invalid}`).
